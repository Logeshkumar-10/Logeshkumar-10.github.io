Data Is Unified.
Meaning Is Not.

Understanding Microsoft Fabric IQ

Logeshkumar Sivakumar May 2026 5 min read Microsoft Fabric · AI · Data Engineering

You moved your data to OneLake. Your reports run on Power BI. Your AI agents can query the lakehouse. But ask two agents the same question about "Revenue" and you will get two different numbers — because one reads the CRM definition and the other reads the finance table. The data is in one place. The meaning still is not.

That is the gap Microsoft Fabric IQ is built to close.

What is Microsoft Fabric IQ?

Fabric IQ is a workload in Microsoft Fabric that unifies data sitting across OneLake and organises it according to the language of the business. The data is then exposed to analytics, AI agents, and applications with consistent semantic meaning and context.

Fabric IQ does not replace your existing data estate. It builds on top of it. Your lakehouses, eventhouses, and Power BI semantic models stay where they are. Fabric IQ adds a shared vocabulary on top of them so that every downstream tool, report, and agent reads from the same definitions.

Introduced at Microsoft Ignite 2025, Fabric IQ is currently in public preview.

The Six Items in the Fabric IQ Workload

Fabric IQ is a collection of six items. Each solves a specific part of the meaning problem.

Ontology preview

The foundation. Defines the enterprise vocabulary — entity types like Customer or Shipment, properties like Customer name and email, relationships like Customer places Order — and binds those definitions to real data in OneLake. Every other item in the workload reads from the Ontology.

Graph preview

Provides native graph storage and compute for nodes, edges, and traversals. Handles relationship-heavy questions that flat SQL joins cannot answer — such as tracing an order through a shipment to a sensor breach to an SLA penalty.

Data Agent

Lets teams build conversational Q&A systems over governed data using plain-language questions. When a Data agent connects to the Ontology, answers reflect business terms rather than raw column names. Users ask "What is our net exposure in retail this quarter?" and the agent returns an answer anchored in the same definition Finance and Risk both agreed on.

Operations Agent preview

Monitors real-time data continuously against Ontology-defined rules and recommends or triggers governed actions without waiting to be asked.

Power BI Semantic Model

The analytical model most teams already have. In Fabric IQ, an Ontology can be generated directly from an existing semantic model — which means the business definitions you have already built in Power BI become the starting point for the entire workload.

Plan preview

Brings financial and operational planning into Fabric — budgets, forecasts, write-back, and approval workflows — built on the same semantic foundation and governed data the rest of the platform uses.

How the Items Work Together

The Ontology is declared once. Graph computes traversals across the relationships the Ontology defines. The Data agent answers questions using those entities and relationships. The Operations agent monitors live signals against the Ontology's rules. The semantic model feeds into or stays consistent with the Ontology. Plan connects historical performance and future intent on the same governed layer.

You do not need all six items on day one. Most teams start by generating an Ontology from an existing Power BI semantic model, then extend into agents and planning as the use case demands.

A Real-World Example of Where This Breaks Down

A bank running credit, retail, and treasury teams off separate data sources defines "Customer Exposure" differently across each function. Their AI agents produce conflicting risk summaries depending on which source they query.

Fabric IQ's Ontology lets the organisation define "Customer Exposure" once and enforce that definition across every downstream report, agent, and planning model that touches the concept. One definition. Zero reconciliation.

When to Start Evaluating Fabric IQ

Fabric IQ requires an existing Microsoft Fabric environment. Specific items — including Ontology and Plan — require tenant admin enablement in the Fabric admin portal before they can be created. Since Fabric IQ is in public preview as of the time of writing, teams should validate behaviour in non-production environments before applying it to governed reporting pipelines.

The clearest signal that your organisation is ready for Fabric IQ: your teams are getting inconsistent answers from the same data, or your AI agents are producing outputs that do not map to how the business actually defines its terms.
